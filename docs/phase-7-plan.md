# Phase 7 plan: reports and audit

## Context
Phases 0–6 are done and committed (last commit `5a67360`). Phase 7 covers two requirements:
- **ADM-18:** generate intake, segregation, inventory, composting, outgoing material and income reports, by date range and purok, as PDF and CSV.
- **ADM-20:** monitor system activity.

Status: **draft, waiting for your go-ahead.** Nothing is built yet.

What already exists:
- The Activity log page (Settings › Activity log) already filters by user and by period (Today / This week / This month / All) and shows When, Who, Action, Record. What is missing from the wireframe and roadmap: a custom date range, an action filter, and export. It also does not yet log report views or exports.
- Every number a report needs is already computed somewhere in `operations/service.py` (`intake_list`, `compliance`, `sorting_view`, `inventory`, `compost_view`, `outgoing_view`, `income_since`), but those functions take "last N days" and no purok. Reports need an exact from/to range and an optional purok.
- There is no Reports page, no "Reports" nav entry and no PDF library in the API image (checked: no `reportlab` or `weasyprint`).

Wireframes: admin `05-reports` (choose), `05b-report-preview` (preview with Export PDF / Export Excel), `05c-report-exported` (exported, Recent reports list), `11-settings-activity`. Staff `03-reports` (STF-09) is the staff side and is not in this phase.

## Decisions
Open questions (recommendation first):
1. **PDF library: ReportLab (recommended).** Pure Python, about 3 MB, no system packages. WeasyPrint (named in the roadmap) needs Pango/Cairo system libraries in the image, which is a heavier install and C: has 18 GB free. ReportLab draws tables directly, which is all these reports are.
2. **"Excel" means CSV (recommended).** The roadmap says CSV and the wireframe says "Export Excel". CSV opens in Excel and needs no library. A real `.xlsx` would add `openpyxl` for little gain.
3. **Recent reports list: store only the history, not the files (recommended).** A `report_exports` row (type, range, purok, format, who, when) is saved on every export. "Download" regenerates the file from the current data with the same settings. Storing the PDF bytes would keep the exact file but needs a file volume or `bytea` rows and a retention rule.

My calls (override any):
- **Preview is the same data as the export.** One service builds a report as `{title, subtitle, summary, columns, rows}`. The page renders it as a table, the CSV writer and the PDF writer both read the same structure, so the three can never disagree.
- **Date range:** From and To (inclusive, Manila days), default the last 30 days. Range limit 366 days. Purok filter: all puroks or one source area. Inventory is a snapshot of stock now, so it ignores the range (the report says "as of <date>").
- **Report contents** (one function each in `reports/builders.py`):

  | Report | Rows | Summary line |
  |---|---|---|
  | Intake | per purok × waste category: deliveries, kg | total deliveries, total kg |
  | Segregation | per purok: deliveries, segregated, compliance % | overall compliance (as in the wireframe) |
  | Inventory | per material × storage area: kg on hand, area capacity % | total kg, as of now |
  | Composting | per batch: start date, status, raw kg in, compost kg out, last temperature and moisture | batches, compost produced |
  | Outgoing material | per approved outgoing request: date, kind (sale / compost / residual), material, kg, buyer or destination | total kg by kind |
  | Income | per approved sale: date, material, kg, price per kg, amount | total income (approved sales only, as in Phase 4) |

- **Only approved outgoing requests count** in the Outgoing and Income reports, the same rule as the Overview.
- **Who can use it:** Reports are admin-only in this phase. Staff reports (STF-09) come with the staff screens.
- **Logging:** previewing, exporting and re-downloading write to the activity log ("Viewed Segregation report", "Exported Intake report as PDF"), as in the activity-log wireframe.
- **Activity log additions:** custom From / To dates, an action filter (Logins, Users and access, Records, Approvals, Reports), and Export CSV of whatever the filters show. Defaults and the current quick buttons stay.
- **PDF look:** school-style document: black and white, report title, "Barangay Sapul MRF" header (a placeholder name for submission), range, generated by and when, summary line, the table, page numbers.
- **Cap:** the preview shows up to 500 rows (with "showing first 500 of N"); CSV and PDF include every row.

## Tests that must pass
- **Builders:** against a small known data set (a few deliveries across two puroks), each report's rows and summary match hand-calculated numbers. Range edges are inclusive. The purok filter narrows every report that has puroks. An empty range returns zero rows, not an error.
- **Outgoing and Income:** pending and rejected requests are excluded; income equals the sum of approved sales.
- **Inventory:** ignores the range and matches the Inventory page total.
- **Export:** CSV has a header row and the same rows as the preview; the PDF starts with `%PDF` and has a non-zero length; the response has the right content type and a sensible filename. A range over 366 days or From after To → 422.
- **History and logging:** each export writes one `report_exports` row and one activity row; previews write an activity row; `GET /reports/recent` is newest first, max 10.
- **Access:** operators and staff → 403; not logged in → 401.
- **Activity:** From / To are inclusive Manila days; the category filter returns only that group; the CSV matches the filtered list.
- **Overall:** every Phase 1–6 test still passes, Ruff is clean, `npm run build` passes, all browser tests pass.
